## Requirements outside the numbered scenario shorthand

- All necessary web domain actions must be available with shared semantics. The current UI supports capture/edit/lifecycle/read/acknowledgement and claim/renew/release/explicit replacement. Structured work/check forms now support criterion evidence, artifacts, follow-up, reconciliation and stale-report preservation. UI selection now exposes planning/execution, inclusion flags, as_of, page size and reasons. Standalone historical observations now support reviewed import on terminal tasks, strict raw JSON validation, conflict recovery and retry retention. The completed operation mapping is in the [UI parity audit](reviews/2026-10-23-ui-parity.md), supported by packaged/Vite browser execution.
- [Backup and recovery](backup-and-recovery.md) documents stopped-writer copying, validation, restore, HTTP rotation and upgrade constraints. `verify` and `auth rotate` are implemented and restore-tested. Unsupported-schema no-write/mixed-directory and pending-recovery guards are implemented and tested. No automatic destructive migration; pre-release scratch stores are not an advertised supported upgrade format.
- Pin the advertised minimum macOS version/CPU and browser/client support to executed evidence. Cross-compilation is insufficient to advertise a platform as tested.
- Keep generation/build commands, formal schemas, examples, constitution and implementation status synchronized. Do not treat the presence of a test or schema file as evidence it passed.
- Complete a final requirement-by-requirement audit before marking the goal achieved. No release/publication or commit is implied by implementation authorization.
