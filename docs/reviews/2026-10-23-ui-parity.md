# UI operation parity audit

Scope: current `web/src` against R7 and the specification interface table. Source inspection establishes available controls and gaps; browser tests remain the execution evidence. This operation mapping is supported by the recorded packaged/Vite acceptance suite and keyboard-only workflow.

| Domain operation | Current UI path | Remaining finding |
| --- | --- | --- |
| Create | New task editor | Implemented: ready/inbox candidate selection and optional stable producer/source/action/occurrence identity. Packaged/Vite tests cover acceptance, manual edits, dismissal, unchanged rediscovery and a distinct period. Existing identity is read-only. |
| Select | Views, date/status/person/follow-up filters, selection options, pagination | Implemented: explicit multiple-status sets, calendar-date or RFC 3339 instant windows, person filtering across views, and undated-only filtering for personal/delegated/all tasks. Browser tests compare exact boundaries with API results, including offsets and microsecond precision. Invalid/incomplete filters clear stale rows. |
| Read/context | Detail, guidance, criteria, sources, claims, follow-ups, observations | Implemented: server-provided missing-context diagnostics render as actionable guidance; absent requirements are not invented by the UI. Packaged/Vite tests verify diagnostics and refresh after edits. |
| Edit | Editor for task/context/guidance/check/source/delegation fields | Fixed: explicit criterion selection preserves existing partial scope; new criteria stay unselected for an existing check and removed criteria are removed from its references. Retain browser preservation tests. |
| Edit delegation | Waiting-for fields | Fixed: actionable tasks retain delegation unless the user clears Keep delegation details. Delegation time is editable as RFC 3339 and preserved exactly on unrelated edits. Source capture timestamps are now editable as RFC 3339, with UTC storage verified through CLI readback. |
| Transition | Accept/dismiss/complete/reopen/resume/needs-more-work with confirmation | Implemented: active-claim edits/transitions use the held token, with explicit override still available. Tokens remain ephemeral and scoped to the selected task. Changing flow while a claim is active requires release or explicit override, even with its token. Retained keyboard-only walkthrough covers capture, acceptance, edit, completion/reopen, claim/release, history and locking. |
| Claim/renew/release | ClaimControls | Existing browser lifecycle tests cover these operations and replacement. Retain token/expiry/conflict checks. |
| Work/check report | ReportControls | Structured evidence, artifacts, follow-up and reconciliation are present; preserve stale-context and uncertain-response tests. |
| Observe/acknowledge | Historical report import and per-observation acknowledgement | Implemented: individual and selected-batch acknowledgements, explicit reasons, paginated selection and revision-conflict refresh. Browser tests cover selected-only effects and lost-response retry without duplicate events on terminal tasks. |
| History | Paginated event timeline and report rendering | Implemented: expandable recorded changes expose updated fields and structured lifecycle/coordination metadata alongside reports. Keyboard, escaped markup and narrow-view checks pass. Retain pagination coverage. |

Silent check-scope/delegation edit changes have been fixed. Context/history and capture controls are now implemented at the recorded scope. The concrete capture/query/claim/batch-acknowledgement gaps identified here are implemented with recorded tests. The final operation mapping and keyboard-only walkthrough are complete at this scope; the full suite passed 18 cases, with 2 scenarios intentionally packaged-only. Do not weaken R7 to match the existing UI. Maintenance commands (`init`, credential management, verification) are installation/administration concerns, separate from task-operation parity.
